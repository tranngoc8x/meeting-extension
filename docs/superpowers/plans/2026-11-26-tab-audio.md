# Audio-only tab capture implementation plan

Goal: implement the approved tabCapture UX, preserving existing local files and bot/account behavior. Spec: ../specs/2026-11-26-tab-audio-design.md. Tracking: meet-ext-w1f; deferred R2 contract remains meet-ext-736. Use Beads for progress rather than Markdown task lists.

## Capture/offscreen

Modify recorder.js start({streamId,meetingUrl,title}) to use getUserMedia({audio:{mandatory:{chromeMediaSource:'tab',chromeMediaSourceId:streamId}},video:false}) and restore ONLY tab audio to context.destination. Keep mixed audio output, ordered local persistence and all cleanup/error handling. Add offscreen.html/js consuming target:'offscreen' messages recording.offscreen.start/stop/status/permissions and emitting target:'background',type:'recording.state' with {state,tabId,meetingUrl}. Start metadata includes tabId and documentId (nullable). Its persistence adapter writes directly to recording-store.js in the same extension origin; no content-script chunk RPCs. Fresh controller instances query actual offscreen status before use.

## Worker controller

Create recording-controller.js createRecordingController(chrome) exposing start(tab?), stop(tabId?), status(tabId?), onState(message,sender), tabClosed(tabId), tabNavigated(tabId). Serialize starts/stops; use chrome.runtime.getContexts/createDocument(USER_MEDIA) before fresh getMediaStreamId. Query offscreen microphone permission first; when missing open microphone.html on explicit start invocation and return clear needsMicrophone state. Send start metadata from actual active Meet tab and meet.status, never from untrusted payload. Broadcast state to target Meet tab; persist status in chrome.storage.session. Update background.js routing: popup exact URL for start, Meet sender validation for own status/stop, exact offscreen URL for state. Add recording shortcut listener; retain original bot detection listeners.

## UI/permission page

Modify recording-ui.js to observe worker status/broadcast and send own stop. Idle primary shows how to invoke July; never calls media APIs. Keep six-second call-exit confirmation and room-change stop, reconnect status after content reinjection. Popup recording section starts/stops via trusted worker messages and shows permission/error states. Add microphone.html/js with one button requesting extension-origin permission and releasing all test tracks. Add activeTab/tabCapture/offscreen permissions, Chrome minimum 116, shortcut and appropriate manifest entry points; remove recorder.js from content scripts.

## Verification/review

Write failing tests before each behavior change. Update obsolete picker tests to audio-tab acquisition, preserve meaningful lifecycle/media tests. Replace content-audio service/integration tests with controller/trust and UI/permission integration tests. Run npm test, syntax and diff checks, review independently, record test limits and close Bead before scoped commit. No deployment, external upload or destructive data changes.

## Verification result — 2026-11-26

Final full suite with CAPTURE_BROWSER_EXECUTABLE set to current Chrome for Testing 158: 71/71 pass, zero skips. Native extension action is invoked through the browser's CDP Extensions.triggerAction on the actual tab target, which grants activeTab (action.openPopup by itself does not). Native tabCapture/offscreen, state routing, stopping all active tab capture, extension IndexedDB, file download and WebM decoding with nonzero audio were verified. The meeting tab produces a synthetic tone and the microphone device is fake. No real microphone, signed-in Meet call, R2 upload or deployment was used. Existing stored-file schema is unchanged; storage/library tests still pass.

Independent review identified failures where Stop could skip closeDocument after a status RPC error, and where active/error snapshots removed Stop from the card/popup. Regression tests reproduced both before fixes. Stop now covers status/startup messaging failures, preserves active when cleanup cannot be confirmed, and both UIs keep Stop available. Pending-start status remains readable for cancellation. Syntax and diff checks pass.

Native harness findings: old Chromium 127 lacks storage.local.setAccessLevel, so it cannot bootstrap this repository's existing token-protection guard. The guard was preserved. Generic fake media UI also intercepts tab capture and yields missing-device errors; the harness uses auto-accept-camera-and-microphone-capture instead. These are test setup constraints, not production fallbacks. R2 orchestration remains explicitly deferred in meet-ext-736.

## UX correction result — v0.4.1 (meet-ext-v07)

Tony's reproduction exposed an extra action popup/Record step and a permission page that required manual return/restart. Removed default_popup and wired the toolbar action directly to recording start/stop; retained the existing account/schedule UI as an options tab. Removed the floating card's guidance-only button, retaining state, Stop, recordings and Settings.

The visible microphone helper now automatically requests permission and keeps its sample stream only until the trusted background handoff establishes offscreen recording for the original tab/room. It releases the sample, closes itself and returns to Meet. Browser permission remains enforced by actual getUserMedia; the readiness marker is advisory. Pending helpers are bound to actual sender tab IDs and original meeting identity, survive worker replacement and cannot revive canceled/closed/navigated intents.

Final full suite: 85/85 pass, zero skips, including the native fresh-profile journey with no global microphone pregrant. One real extension action opens the first-use helper; it automatically closes while native tab capture continues. A subsequent action starts directly without any new page, another action stops, and downloaded WebM decodes with nonzero samples. Synthetic meeting audio and fake microphone only; no real joined Meet, R2 send or deployment claimed. The previous pregranted-permission native test was replaced because it did not establish this UX.

Independent review identified cancellation during helper creation/registration and queued/in-flight handoff. Failing regressions reproduced these before fixes, including Chrome-like cloned session storage and replacement-worker identity. Final syntax and diff checks passed; stored recording schema/data were preserved.
